# static-splatting-image-to-3D — one photo ➜ 3D Gaussian Splatting

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/saranunt-0/static-splatting-image-to-3D/blob/main/notebooks/single_image_to_3dgs_colab.ipynb)

Turns **a single photo** (no video, no COLMAP) into a standard 3D Gaussian Splatting scene. You can
look around in it **near the spot the photo was taken from**: head-motion parallax, a small
sideways step or a short dolly into a corridor. Output opens in SuperSplat, Blender, Unreal, Unity
and browsers.

| Step | What happens | Tool |
|---|---|---|
| 1. Geometry | metric depth, camera FoV, normals | **MoGe-2** (MIT) · fallback Depth Anything V2 (ONNX) |
| 2. Lift | one surface-aligned Gaussian per pixel (pixel-footprint covariance); depth edges cut by a parallax test | `ssplat/geometry.py`, `lift.py` |
| 3. Hidden layer | background behind each occluding edge + beyond the frame: planar depth continuation + **LaMa** inpainting | `ssplat/occlusion.py` |
| 4. Refine | fit to the photo, geometry anchored to the depth map | pure-PyTorch 3DGS rasterizer (`rasterize.py`) |
| 5. Export | `.ply` · `.html` viewer · `.spz` · `.glb` · preview videos | `export.py`, `render.py` |

**Why this design and not just "depth → point cloud → train 3DGS on the image"?** See
[docs/RESEARCH.md](docs/RESEARCH.md): survey (SHARP, Lyra, GEN3C, MoGe-2/3, Depth Anything 3…),
design decisions, and a ground-truth benchmark on a synthetic corridor.

## Quick start

**Colab:** click the badge, pick a GPU runtime, run the cells.

**Command line** (Linux/macOS; GPU optional, CPU works but is slow):
```bash
python -m ssplat.setup_env                       # deps + MoGe-2 + splat-transform (no CUDA compile)
python -m ssplat.run --input corridor.jpg --work work/corridor
python -m ssplat.run --input corridor.jpg --work work/corridor_fast --preset fast \
    --set depth.model=dav2 --set depth.fov_deg=65          # no MoGe: relative depth + your FoV
python -m ssplat.setup_env --sharp && \
python -m ssplat.run --input corridor.jpg --work work/corridor_sharp --set method=sharp   # Apple SHARP
```
Presets: `quality` (1024 px, 500 refinement steps), `balanced`, `fast` (512 px, CPU-friendly).
Every option is documented in [ssplat/config.py](ssplat/config.py); override any with
`--set section.field=value`. The most important one is **`occlusion.max_baseline`**: how far you
plan to move, as a fraction of the median scene depth (default 0.08).

Outputs in `--work`: `export/scene.ply` (+ `scene_viewer.html`), `videos/scene_{swing,circle,dolly}.mp4`,
`preview_grid.png` (3×3 novel views; centre = the photo), `debug/` (depth, occlusion edges,
hidden layer), `summary.json`.

## Limits (read these)
* **Small motion only.** Anything the photo did not see is synthesised: behind occluders and
  beyond the frame. Plausible for a few % of the scene depth; it falls apart if you walk far.
  For walking *down* the corridor you need a generative model (see RESEARCH.md §2).
* **Inpainting is LaMa**, which is good at walls, floors and tiles and blurry on complex objects.
  The hidden layer is where artefacts appear first.
* **Flat colour** (SH degree 0). One photo cannot tell view-dependent shine from texture.
* **Scale** is metric with MoGe-2; with Depth Anything V2 it is arbitrary (median depth := `depth.median_depth`).
* Verified here on CPU only. MoGe-2 and SHARP were tested for wiring only (random weights; their
  checkpoints could not be downloaded in the development sandbox). The GPU path is the same
  PyTorch code.
